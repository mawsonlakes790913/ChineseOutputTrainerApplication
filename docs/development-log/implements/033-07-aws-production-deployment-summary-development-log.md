# 033-07 AWSへのデプロイと本番環境構築の総括（実装ログ）

## はじめに

第31章から第33章にかけて、ローカル環境で開発したChinese Output ForgeをAWS上へデプロイし、インターネットから利用できる本番環境を構築した。

本章では、一連の実装で構築・変更した構成と、最終的な到達点を整理する。各サービスの設定手順や調査過程は、対応する第31〜33章の実装ログに記録している。

## 1. 第31章：高可用性構成の構築

最初に、高可用性を重視したAWS環境を構築した。

- VPC、Subnet、Route Table、Internet Gateway、NAT Gatewayを使用したネットワーク構成
- Elastic Beanstalk、EC2、Application Load Balancer（ALB）、Auto Scalingを組み合わせた冗長構成
- Amazon RDSのMulti-AZ構成
- Route 53による独自ドメインの設定とHTTPS通信
- CloudWatchとAmazon SNSによる監視・通知

構築後、アプリケーションが正常に動作することを確認した。

## 2. 第32章：低コスト構成への移行

Chinese Output Forgeは個人開発のWebアプリケーションであり、現段階では高可用性を維持するためのランニングコストを抑えることを優先した。

そのため、構成を次のように変更した。

| 対象 | 移行前 | 移行後 |
|---|---|---|
| RDS | Multi-AZ | Single-AZ |
| Elastic Beanstalk | Load Balanced | Single Instance |
| EC2 | 複数インスタンスによる冗長構成 | 1台 |
| ALB・NAT Gateway | 使用 | 不要となったリソースを整理 |

移行後も、独自ドメインからのアクセス、HTTPS通信、RDSとの接続など、主要機能が正常に動作することを確認した。

## 3. 第33章：Amazon SESによるメール送信環境の構築

本番環境で使用するメール送信機能を整備した。

- Amazon SESに`chinese-output-forge.com`を送信ドメインとして登録
- Route 53にSPF・DKIM・DMARCに関するDNSレコードを設定
- SESの本番アクセスを申請し、承認を確認
- Spring Bootのメール送信処理をAWS SDKによるSES API呼び出しへ変更
- EC2のIAMロールにメール送信権限を付与
- `noreply@chinese-output-forge.com`から会員登録完了メールやパスワード再設定メールを送信できる構成へ変更
- メール送信失敗時の例外処理とユーザー向けエラーメッセージ表示を整備

また、デプロイ後にEC2上のNginx設定が維持されない問題への対応として、HTTPS設定ファイルをアプリケーションのデプロイ成果物に含める方式へ変更した。

なお、メール送信失敗時のエラーメッセージについては、実装内容とMavenビルドを確認した一方、SESの送信エラーを意図的に発生させる画面表示テストは実施していない。

## 4. 一連の実装を通じて構築した環境

第31〜33章では、Spring Bootアプリケーションをクラウド上で動かすだけでなく、ネットワーク、セキュリティ、データベース、可用性、監視、HTTPS通信、DNS、メール認証を含む本番環境を構築した。

高可用性構成を一度構築した後、低コスト構成へ移行することで、AWSリソースの役割と構成変更による影響を実際の作業を通じて確認できた。また、設定の不備や想定外の動作が生じた際には、ログやAWSの設定画面、サービスの仕様を確認して対応した。

## まとめ

Chinese Output Forgeについて、AWSへのデプロイ、独自ドメインによるHTTPS公開、データベースの運用、監視・通知、Amazon SESを利用したメール送信機能まで一通り整備した。

**これをもって、Chinese Output Forgeの初期開発とAWSへの本番デプロイを完了とする。**
