# 023-11 スマートフォン向けレスポンシブ対応 — 学習ログ

## はじめに

これまでは主にPCのブラウザで画面を確認していたが、スマートフォンの実機で操作すると、横並びの見出しや選択肢が極端に狭くなり、文字が1文字ずつ折り返される問題が見つかった。特に共通ヘッダー、通常学習・AI生成学習メニュー、問題一覧で顕著だった。

今回の対応では、単にすべての文字を小さくするのではなく、**PCでは従来の表示を維持し、狭い画面では情報の並べ方そのものを変更する**ことを重視した。

## 1. 折り返しの問題は文字だけでなく親要素の配置から考える

最初に理解したのは、文字が不自然に折り返される原因が、必ずしも文字サイズや文章の長さだけではないという点である。

例えば、通常学習メニューの難易度選択では、初級・中級・上級の3項目を横並びにしていたため、スマートフォンでは各項目に十分な幅を確保できなかった。`text-nowrap`で改行を禁止する方法も試したが、今度は画面の外にはみ出してしまった。

つまり、**改行を防ぐことと、画面内に収まることは別の問題**である。そこで親要素のFlexboxを、画面幅に応じて縦並びと横並びに切り替える方法を採用した。

```html
<div class="d-flex flex-column flex-md-row gap-3">
```

`flex-column`を基本として、`md`以上では`flex-md-row`で横並びに戻す。Bootstrap 5の`md`ブレークポイントは768pxであり、JavaScriptで画面幅を判定しなくてもCSSのクラスで配置を変更できる。

この考え方は、通常学習だけでなくAI生成学習の見出し・説明文や難易度選択にも応用した。一方、問題出題画面の長文が自然に複数行になることは修正対象とせず、**読みにくさや操作のしづらさを生む折り返しだけを改善する**方針とした。

## 2. BootstrapのUtilityを組み合わせて表示環境ごとの差を吸収する

共通ヘッダーでは、PC向けの横一列の配置をスマートフォンでも維持していたため、アプリ名や「学習言語」が窮屈になっていた。ヘッダー全体をスマートフォンでは2段、PCでは1段に切り替えることで、各要素が使える横幅を確保した。

```html
<div class="container d-flex flex-column flex-md-row
            justify-content-between align-items-md-center gap-3">
```

今回の修正から、BootstrapのUtilityにはそれぞれ異なる役割があることを整理できた。

- `flex-column`・`flex-md-row`：要素を並べる方向を切り替える。
- `align-items-md-center`：一定以上の画面幅でだけ中央揃えを適用する。
- `text-nowrap`：アプリ名や短いラベルの途中改行を防ぐ。
- `ms-md-auto`：PC表示時だけ左側の自動余白を使い、操作グループを右側へ寄せる。
- `me-5 me-md-0`など：スマートフォンで必要な余白を、PC表示時には解除する。

また、通常学習メニューでは`<h3>`に`h4`クラスを付け、**HTMLの見出し階層を維持したまま見た目のサイズだけ変更**した。文言の短縮や不要なアイコンの削除も行い、レイアウトの調整だけでは解消しにくい窮屈さを減らした。

重要なのは、特定のUtilityを一律に適用することではなく、要素ごとに「改行を防ぐべきか」「縦に並べるべきか」「余白を変えるべきか」を判断することである。

## 3. 一覧表は縮小するより表示形式を変える方が適切な場合がある

問題一覧には、日本語・中国語の問題文に加え、文法・構造、難易度、生成元、理解度、お気に入り、各種操作など多くの情報がある。PCのテーブルをそのままスマートフォンに表示すると、各列の幅が不足し、問題文が数文字ずつ折り返されるうえ、横スクロールが必要になった。

そこで`/user/question/list.html`では、**768px以上は既存のテーブル、768px未満は1問ずつのカード**として表示形式を分けた。

```html
<!-- PC・タブレット向け -->
<div class="table-responsive d-none d-md-block">
    <!-- 既存のテーブル -->
</div>

<!-- スマートフォン向け -->
<div class="d-md-none">
    <div th:each="question : ${questionList}" class="card mb-3">
        <!-- 1問分の情報と操作 -->
    </div>
</div>
```

ここではBootstrapのDisplay Utilityで表示を切り替え、Thymeleafの`th:each`では同じ`${questionList}`を使用した。**画面ごとに別のデータ取得処理を作る必要はなく、同じデータを異なる形で見せられる**ことが分かった。

さらに、スマートフォン用カードでも`detailButton`、`evaluationButton`、`favoriteButton`、`questionListButton`などの既存クラスや、問題IDを表す属性、モーダルの対象指定を維持した。これにより、見た目は異なってもJavaScriptのイベント処理や削除フォームを共用できる。

ただし、PC版とスマートフォン版のDOMは別々に存在するため、今後項目を追加・変更する際には両方の表示を確認する必要がある。**データと操作を共通化しつつ、表示部分の重複は保守対象として意識する**ことも学びとなった。

## 4. 画面下部の余白も操作性の一部

ログイン後のホーム画面では、歓迎メッセージが追加されると、最下部の「このアプリについて」ボタンがスマートフォンのブラウザUIに近づいていた。

この問題には、最後のボタンだけでなくメニュー全体の親要素へ`mb-4`を追加した。ログイン状態によって表示される項目が変わっても、最下部に余白を確保しやすくなるためである。

ここから、**画面にすべての要素が収まっていることと、無理なく操作できることは同じではない**と分かった。特にスマートフォンでは、ブラウザの操作領域や画面端との距離も考慮する必要がある。

## 5. 実機確認と修正範囲の判断

今回の実装記録では、スマートフォンの実機で表示を確認し、共通ヘッダー、通常学習・AI生成学習メニュー、ホーム画面下部、`/user/question/list.html`の問題一覧について調整した。問題一覧はカード表示になり、文章が極端に細かく折り返されず、各操作を横スクロールなしで利用できる配置になったことを確認している。

一方、問題リスト内の一覧についても表示上の問題は挙げられているが、元の実装記録には個別の修正コードや確認結果が残っていない。したがって、今回の学習ログでも対応完了とは扱わない。

## まとめ

今回の対応を通じて、レスポンシブ対応は単に画面幅に合わせて縮小する作業ではなく、**画面幅ごとに適切な情報の配置と操作方法を選ぶ設計**だと理解した。

短いラベルは改行を防ぎ、横並びが窮屈な要素は縦並びにし、情報量の多いテーブルはカードへ切り替える。一方で、Thymeleafのデータや既存JavaScriptの操作処理はできるだけ共通化する。このように表示と機能の責務を分けることで、PCの一覧性を維持しながらスマートフォンの読みやすさと操作性を改善できた。

これで、023-01から023-11までの学習ログの分割も完了した。
