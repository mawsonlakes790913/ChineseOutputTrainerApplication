# 031-06 AWS高可用性構成⑥｜構築した高可用性環境の動作確認（学習ログ）

この章では、Chinese Output ForgeのAWS高可用性構成を完成させた後、各リソースの設定と実際の通信を確認する過程で学んだことを記録する。確認に使用した具体的な操作・コマンド・スクリーンショットは、対応する実装ログ031-06を参照する。

## リソースの稼働とサービスの正常動作は別の確認が必要

最終確認では、Route 53 → ALB → EC2 → RDSというWebアクセスの経路、Private EC2 → NAT Gateway → Internetという外向き通信の経路、CloudWatch → SNS → Emailという監視通知の経路を、それぞれ確認した。

最初はAWSコンソール上でリソースが作成され、稼働状態になっていれば構成が完成したと考えがちだった。しかし、EC2が「実行中」であることと、ALBから正常にリクエストを転送できることは同じではない。

そのため、EC2の状態とは別に、ALBのTarget Groupで2台とも`Healthy`になっていることを確認した。Auto Scaling Groupについても、Desired / Min / Maxがいずれも2であることに加え、実際に2台が所属していることを確認した。

この経験から、**リソースが存在すること、期待する設定になっていること、実際にサービスとして利用できることは、分けて確認する必要がある**と学んだ。

## RDSとNAT Gatewayの確認で学んだこと

RDSについては、Multi-AZ設定の有無だけでなく、EC2からRDSの5432番ポートへ到達できることと、アプリケーションからデータベースを利用できることを確認した。

また、NAT Gatewayについても、ルートテーブルの設定を確認するだけで終わらせず、Private EC2から`curl`を実行して外部へのHTTPS通信ができることを確かめた。

特に、Private Subnetに配置したEC2はインターネットから直接アクセスできない一方、適切な経路があれば外部APIなどへ通信できる。この違いを、構成図や設定画面だけでなく実際の通信結果として確認できたことが大きかった。

## 高可用性構成を完成させて理解が深まったこと

今回のAWSデプロイで最も大きかったのは、AWSサービスを単独の用語として覚えるのではなく、**Spring Bootアプリケーションを動かす一つのシステムとして結び付けて理解できたこと**だった。

特に、次の点は実装前よりも明確になった。

- 高可用性を高めるほどランニングコストも増えるため、サービス要件に応じた判断が必要になる。
- Public / Private Subnetの区別は名前だけでなく、ルーティングなどの構成によって決まる。
- Private EC2でもNAT Gatewayを経由して外部へ通信できる。
- Security GroupはALB・EC2・RDSの通信経路に沿って役割を分けられる。
- Elastic Beanstalkの背後ではEC2、ALB、Auto Scaling Groupなどが動いている。
- EC2を複数台にすると、HTTPセッションやCSRFトークンの扱いが問題になる場合がある。
- Private RDSへのデータ移行には、SSMポートフォワーディングを利用できる。
- PostgreSQLの復元では、外部キーの依存関係やOwnerの違いを考慮する必要がある。
- Parameter Storeから読み込むSpringのプロパティと、SDKが参照するOS環境変数は同じではない。
- `502 Bad Gateway`などのエラーは、画面上のステータスだけで判断せず、アプリケーションログまで確認する必要がある。
- HTTPS通信にはDNS、証明書、ALBリスナー、Security Groupなど複数の設定が関係する。
- 監視はAlarmを作成するだけでなく、実際に異常条件を発生させて通知まで確認する必要がある。

これらは各章で扱った学びだが、最終的に一つのアプリケーションが正常に動作することを確認して、相互の関係を整理できた。

## 次の低コスト構成への移行に向けて

今回構築した高可用性構成は、AWSの各サービスの役割と連携を学ぶ上では有用だった。一方で、Chinese Output Forgeは個人開発の学習アプリであり、常時高い可用性が求められるサービスではない。

そのため、**高可用性構成を一度完成させて確認した上で、実際の用途と費用に合わせて低コスト構成へ変更する**方針とした。

次の032では、今回確認したリソースの役割を踏まえ、何を残し、何を削減するかを判断しながら構成を変更する。
