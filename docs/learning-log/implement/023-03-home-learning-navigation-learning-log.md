# 023-03 Home・学習画面のナビゲーション改善 — 学習ログ

## はじめに

本章では、Home画面とトレーニング完了画面のナビゲーション改善、各学習モードの説明文の追加、出題条件に合わせた表示文言の見直しについて振り返る。実装コードは実装ログ「023-03 Home・学習画面のナビゲーション改善」に譲り、変更した理由と学んだ点を整理する。

## 1. Home画面の表示内容の拡充

主要機能が揃った段階では、Home画面を単なる入口にするより、各学習モードへ直接移動できる構成の方が使いやすいと考えた。

ThymeleafとSpring Securityの`sec:authorize`を組み合わせることで、ログイン状態に応じてリンクやボタンの表示を切り替えられる。

通常学習、復習、AI生成学習、ユーザーメニュー、アプリ概要への導線をまとめ、ログインが必要な機能は未ログイン時に表示しないようにした。ただし、`sec:authorize`はリンクの表示制御であり、実際のアクセス権限はサーバー側の認可設定で保証する必要がある。

## 2. トレーニング完了画面の拡充

学習終了後の行動は、同じモードの継続だけとは限らない。復習やAI生成学習へ進みたい場合にも、Home画面を経由せず移動できるようにしたかった。

画面遷移は個々のページだけでなく、**ユーザーが操作を終えた直後に次に何をしたいか**まで考える必要がある。

Home画面と同様のメニュー導線を設け、ログイン状態による表示制御も揃えた。画面ごとに利用可能な機能が矛盾しないようにした。

## 3. 各モードのメニュー画面への説明文の追加

「通常学習」「復習」といった機能名だけでは、対象となる問題や学習方法の違いが伝わりにくい。選択前に機能の概要を理解できるようにするため、各メニューに説明文を追加した。

機能が実装されていても、画面上の説明が不足しているとユーザーは適切なモードを選べない。UIの完成度には、操作部品だけでなく説明文の分かりやすさも含まれる。

通常学習・復習・AI生成学習・問題リストのメニューに説明を加え、言語別のメッセージ定義と連携させた。

## 4. 各画面の説明文と表示文言の修正

機能の説明文に曖昧な部分があり、実際の出題対象や利用条件を誤解される可能性があった。重大な機能不具合ではないが、利用者の混乱を減らすために修正した。

表示文言は単なる装飾ではなく、**アプリが何をするかをユーザーに伝える仕様の一部**である。特に「復習対象となる条件」や「AI生成学習の元になる問題」の説明は、実装の動作と一致していなければならない。

通常学習では保存済みのAI生成問題も対象に含まれること、復習では理解度を記録した問題が対象となることなどを明確にした。また、AI生成学習の説明を実際の生成元の条件に合わせて修正し、言語別の文言にも反映した。

実装ログでは、リスト内の問題でも現在の学習対象言語と異なる場合は出題対象外になること、理解度ボタンを押していない問題はAI生成の対象にならないことも明示している。**ユーザーが画面上の説明から予想する動作と、実際の検索・出題条件を一致させること**が重要だった。

## まとめ

今回の改善を通じて、ナビゲーションと説明文は別々の装飾ではなく、ユーザーが学習モードを選択し、次の操作を判断するための機能であると分かった。

Home画面と完了画面の導線を整えるだけでなく、ログイン状態に応じた表示制御と、出題条件に即した多言語の説明を揃えることで、アプリ全体の使いやすさを改善した。
